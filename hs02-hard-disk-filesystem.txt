--- Slide 3 ---
Il problema 
 Salvare non vuol dire capire 
 Quando premi "Salva", il computer deve decidere dove mettere i dati, come ritrovarli e chi può leggerli. Questo non avviene per magia: è un processo a più strati. 
 Il disco è il magazzino fisico. Il file system è l'inventario che mappa nomi e posizioni. Le cartelle sono scaffali logici. I file sono gli oggetti conservati, identificati da un percorso univoco. 
 Analogia: Un archivio cartaceo senza indice è inutile quanto un disco pieno senza file system. 
 
 
 📦 File Un contenitore di dati con contenuto e nome: testo, immagine, video, programma o archivio compresso. 
 🗂️ Cartella Un nodo logico che raggruppa nomi e percorsi. Non è una scatola fisica, ma un riferimento nel catalogo del file system. 
 🧭 Percorso La sequenza di cartelle che porta a un file, dalla radice del volume fino al nome del file stesso. 
 🧾 Metadati Informazioni associate al file: dimensione, data di creazione e modifica, permessi di accesso, proprietario.

--- Slide 4 ---
Dischi magnetici 
 Hard Disk HDD 
 Un HDD usa uno o più piatti di metallo rivestiti di materiale magnetico che ruotano a 5400 o 7200 giri al minuto. Una testina galleggia a pochi nanometri dalla superficie e magnetizza o rileva piccole aree per scrivere e leggere bit. 
 I dati sono organizzati in tracce circolari, suddivise in settori. Il controller traduce indirizzi logici in posizioni fisiche sul piatto. Il tempo necessario a posizionare la testina si chiama latenza di ricerca . 
 💡 Idea chiave Ottimo per grandi archivi: foto, video, backup a basso costo per gigabyte. Più lento e più delicato negli urti rispetto a un SSD proprio perché ha parti meccaniche in movimento.

--- Slide 5 ---
Memoria flash 
 SSD: veloce, silenzioso, senza parti mobili 
 Un SSD memorizza dati in celle di memoria flash NAND. Non ha piatti né testine: i dati vengono letti e scritti elettronicamente in microsecondi, rendendo l'accesso casuale molto più rapido di qualsiasi HDD. 
 
 ⚡ Veloce Tempi di accesso nell'ordine dei microsecondi. Sistema operativo e programmi si avviano in pochi secondi. 
 🔇 Silenzioso Nessun piatto in rotazione, nessuna testina meccanica. Perfetto per laptop e ambienti silenziosi. 
 🧮 Usura gestita Le celle flash supportano un numero limitato di cicli di scrittura. Il controller distribuisce le scritture uniformemente tramite wear leveling . 
 
 TRIM Il comando TRIM informa l'SSD quali blocchi non sono più usati dal file system, permettendogli di prepararli per la prossima scrittura e mantenere velocità e durata nel tempo.

--- Slide 6 ---
Unità di misura 
 Bit, byte, KB, MB, GB, TB 
 Tutto ciò che un computer archivia è composto da bit. Conoscere le unità di misura aiuta a capire quanto spazio occupa un file e quanta capacità ha un disco. 
 
 Unità Cosa significa Esempio pratico 
 bit La più piccola unità di informazione digitale: 0 oppure 1. La base di tutta la logica digitale e delle trasmissioni. 
 byte 8 bit raggruppati insieme. È l'unità base per i file. Un carattere ASCII occupa 1 byte; un carattere UTF-8 può occuparne fino a 4. 
 KB / MB / GB Kilo, Mega, Gigabyte: mille, un milione, un miliardo di byte circa (potenze di 10 dei produttori). Foto JPG ≈ 3–8 MB; film HD ≈ 4–15 GB; sistema operativo ≈ 20–50 GB. 
 TB Terabyte: mille gigabyte circa. I dischi moderni arrivano a 20 TB e oltre. Archivi fotografici, backup aziendali, server NAS domestici. 
 
 Attenzione: i produttori dichiarano capacità in multipli decimali (1 TB = 1.000.000.000.000 byte). Il sistema operativo, che usa potenze di 2, mostra un valore leggermente inferiore (es. circa 931 GiB invece di 1 TB).

--- Slide 7 ---
Prima del file system 
 Partizioni e formattazione 
 Un disco fisico può essere diviso in partizioni: aree logicamente separate che il sistema operativo riconosce come volumi indipendenti, ognuno con il proprio file system e lettera di unità (su Windows) o punto di mount (su Linux/macOS). 
 Un uso tipico è avere una partizione per il sistema operativo e un'altra per i dati personali: così si può reinstallare l'OS senza toccare i file utente. Un disco può ospitare anche più sistemi operativi su partizioni separate. 
 Formattare significa inizializzare una partizione con un file system specifico, creando le strutture dati necessarie per gestire file e cartelle. Di norma cancella l'indice e rende lo spazio riutilizzabile, anche se i dati fisici restano finché non vengono sovrascritti.

--- Slide 8 ---
Il catalogo 
 Cos'è un file system 
 È il metodo con cui il sistema operativo organizza nomi, cartelle, posizione dei blocchi dati, permessi e spazio libero su una partizione. Senza file system, il disco sarebbe solo una sequenza anonima di bit inaccessibili. 
 Il file system mantiene un indice: sa dove inizia ogni file, quanto è grande, chi può leggerlo e quando è stato modificato l'ultima volta. Quando elimini un file, di solito viene rimosso solo dall'indice; i dati fisici restano sul disco finché nuove scritture li sovrascrivono. 
 
 🏷️ Nomi e struttura Associa nomi leggibili a blocchi fisici sul disco, organizzandoli in una gerarchia di cartelle navigabile. 
 🧱 Blocchi e cluster Divide la partizione in unità di allocazione (cluster). Un file occupa uno o più cluster contigui o sparsi. 
 🔐 Funzioni avanzate I file system moderni aggiungono journaling per la resilienza, permessi per la sicurezza, snapshot e cifratura.

--- Slide 9 ---
Albero delle cartelle 
 Percorsi: dove si trova un file 
 Un file non è solo "sul computer": ha un percorso preciso. Il percorso descrive la strada dalla radice del volume fino al nome del file, cartella per cartella. È l'indirizzo univoco che il sistema usa per trovarlo. 
 Esistono due tipi di percorso: assoluto , che parte dalla radice e identifica il file senza ambiguità, e relativo , che parte dalla cartella corrente ed è più corto ma dipende dal contesto. 
 Windows: C:\Utenti\Sara\cv.pdf Linux/macOS: /home/sara/cv.pdf 
 Su Windows la radice è la lettera dell'unità (es. C:\ ). Su Linux e macOS esiste una sola radice ( / ) e i dischi aggiuntivi vengono montati come sottocartelle.

--- Slide 10 ---
Informazioni nascoste 
 Metadati e permessi 
 Ogni file porta con sé informazioni che vanno oltre il contenuto. I metadati sono gestiti dal file system e sono invisibili nella navigazione quotidiana, ma fondamentali per sicurezza, backup e ricerca. 
 
 📏 Dimensione Quanti byte occupa il contenuto del file e quanti blocchi reali usa sul disco. Possono differire per via della granularità dei cluster. 
 🕒 Date Data di creazione, ultima modifica e ultimo accesso. Utili per ordinare file, pianificare backup incrementali e risolvere conflitti di versione. 
 🔑 Permessi Chi può leggere, modificare o eseguire il file. Su sistemi multiutente determinano la sicurezza e la privacy dei dati personali. 
 
 ⚠️ Attenzione Copiare un file tra file system diversi può far perdere metadati: permessi NTFS su FAT32, tag estesi, date di creazione o attributi speciali. Usare strumenti di backup che preservano i metadati quando necessario.

--- Slide 11 ---
Compatibilità 
 FAT32 ed exFAT 
 FAT32 è uno dei file system più antichi ancora in uso, nato negli anni Novanta con Windows 95. La sua longevità è dovuta alla compatibilità quasi universale: lo riconoscono PC, Mac, TV, fotocamere, console di gioco e lettori multimediali di ogni generazione. 
 
 Formato Punti forti Limiti principali 
 FAT32 Compatibilità massima: supportato da quasi tutti i dispositivi prodotti negli ultimi 30 anni, incluse TV, console e fotocamere. Un singolo file non può superare i 4 GB (limite storico a 32 bit). Nessun journaling, nessun permesso utente, nessuna cifratura nativa. 
 exFAT Supera il limite dei 4 GB di FAT32. Buona compatibilità tra Windows, macOS e Linux moderni. Ideale per schede SD e chiavette USB ad alta capacità. Non ha journaling integrato: uno spegnimento improvviso durante la scrittura può corrompere l'indice. Non adatto come file system di sistema. 
 
 Regola pratica: usa FAT32 per dispositivi e lettori vecchi dove la compatibilità è prioritaria; usa exFAT per trasferire file grandi (video, ISO) su dischi e chiavette condivisi tra sistemi diversi.

--- Slide 12 ---
Windows 
 NTFS 
 NTFS (New Technology File System) è il file system di default per i dischi di sistema Windows dalla versione NT in poi. Progettato per ambienti professionali, offre robustezza, sicurezza e funzioni avanzate che FAT32 non può garantire. 
 Su Linux e macOS è possibile leggere partizioni NTFS quasi sempre, ma scrivere richiede driver aggiuntivi (es. NTFS-3G su Linux). Per chiavette da condividere con sistemi non Windows, exFAT resta una scelta più universale. 
 
 
 🧾 Journaling Registra le operazioni in un log prima di eseguirle. Se il sistema si spegne improvvisamente, il disco può recuperare uno stato coerente all'avvio successivo. 
 🔐 ACL e cifratura Permessi granulari per utenti e gruppi tramite Access Control List. Supporta anche la cifratura EFS (Encrypted File System) a livello di cartella o file. 
 📦 File grandi Nessun limite pratico da 4 GB. Un singolo file video può occupare decine di GB senza problemi su NTFS. 
 🪟 Scelta naturale È la scelta standard per il disco principale e le partizioni dati di un PC Windows moderno. Ottimizzato per prestazioni su sistemi Windows.

--- Slide 13 ---
Linux e macOS 
 Btrfs, ext4, APFS 
 Il mondo Linux e Apple ha sviluppato file system propri, ottimizzati per i rispettivi sistemi operativi e carichi di lavoro. Ogni formato risolve priorità diverse: stabilità consolidata, funzioni avanzate o integrazione con l'hardware Apple. 
 
 Btrfs File system moderno per Linux con snapshot istantanei, checksum dei dati per rilevare corruzione silenziosa, compressione trasparente e gestione flessibile di volumi e sottovolumi. Usato di default su Fedora e openSUSE. 
 ext4 Il cavallo di battaglia di Linux: stabile, ben testato, supportato ovunque. Journaling affidabile, buone prestazioni generali. È ancora la scelta di default su Debian, Ubuntu e molte distribuzioni server. 
 APFS Apple File System, introdotto con macOS High Sierra e iOS 10.3. Ottimizzato per SSD, con snapshot, cifratura nativa, clonazione efficiente dei file e timestamp ad alta precisione. Sostituisce il vecchio HFS+. 
 
 💡 Nota sul nome Si scrive Btrfs (B-Tree FS), spesso pronunciato "butter FS". Non è "BRTFS" e non si legge lettera per lettera. Il nome deriva dalla struttura dati B-tree che usa internamente per indicizzare file e metadati.

--- Slide 14 ---
Metodo 
 Organizzare i file 
 Un buon archivio digitale non dipende solo dal disco o dal file system: dipende da nomi chiari, strutture di cartelle coerenti e abitudini mantenute nel tempo. Il file system sa dove sono i tuoi file; solo tu sai cosa contengono. 
 Se non riesci a ritrovare un file in meno di trenta secondi, per te è quasi come se fosse perso. Investire cinque secondi in un buon nome al momento del salvataggio fa risparmiare ore di ricerca in futuro. 
 Regola: Nomina i file come se dovessi ritrovarli tra cinque anni, senza ricordare nulla del contesto. 
 
 
 1. Nomi chiari e ordinabili 2026-06-25_preventivo_rossi.pdf è meglio di nuovo2_finale_OK.pdf . La data ISO all'inizio ordina i file cronologicamente in qualsiasi strumento. 
 2. Cartelle per progetto Raggruppa tutto ciò che serve insieme: documenti, immagini, fatture, versioni bozza. Una cartella per progetto, sottocartelle per tipo di file. 
 3. Versioni esplicite Usa date o numeri di versione nel nome. Evita dieci file chiamati "finale" — usa v1 , v2 , o la data come suffisso.

--- Slide 15 ---
Prestazioni 
 Frammentazione, spazio libero e salute 
 Con il tempo i dischi si riempiono e le prestazioni possono degradare. Capire la frammentazione e la gestione dello spazio aiuta a mantenere il sistema veloce e i dati al sicuro. 
 
 🧩 Frammentazione HDD Sugli HDD i blocchi di un file possono finire in aree fisicamente distanti del piatto. La testina deve spostarsi tra posizioni diverse, rallentando la lettura. La deframmentazione riordina i blocchi per renderli contigui. 
 🚫 Non deframmentare gli SSD Gli SSD accedono a qualsiasi blocco alla stessa velocità: la frammentazione non li rallenta. Deframmentarli aggiunge scritture inutili che consumano i cicli delle celle flash, riducendo la vita del disco. 
 📉 Spazio libero Un disco quasi pieno rallenta sia HDD che SSD. Gli SSD hanno bisogno di spazio libero per il wear leveling e le operazioni TRIM. Lasciare almeno il 10–15% libero è una buona pratica generale. 
 
 Salute del disco: monitora i segnali SMART (Self-Monitoring, Analysis and Reporting Technology) con strumenti come CrystalDiskInfo o smartmontools. Rumori di clic ripetuti su un HDD sono un segnale di guasto imminente: fai subito un backup.

--- Slide 16 ---
Ridurre peso 
 File compressi 
 La compressione analizza i dati alla ricerca di sequenze ripetute e schemi prevedibili, poi li rappresenta in forma più compatta. Un file di testo con molte parole ripetute può ridursi del 70–80%; un video già codificato quasi per niente. 
 Due famiglie Senza perdita (lossless): ZIP, PNG, FLAC. Puoi ricostruire esattamente l'originale, bit per bit.
 Con perdita (lossy): JPEG, MP3, video H.264/H.265. Si eliminano dettagli meno percepibili per risparmiare spazio. Non si può tornare all'originale. 
 
 
 📝 Testo e codice Si comprime molto bene perché contiene molte parole e sequenze ripetute. Un file di testo di 1 MB può diventare 100–200 KB in ZIP. 
 📷 Foto JPEG È già compressa con perdita: aggiungere un archivio ZIP attorno porta pochissimo beneficio e solo confusione. 
 🎬 Video Già compresso con codec come H.264 o H.265. Comprimerlo ulteriormente spesso aumenta le dimensioni o degrada la qualità. 
 📁 Cartelle intere Un archivio compresso raccoglie molti file in un solo contenitore: pratico per allegati email e condivisione.

--- Slide 17 ---
Archivi 
 ZIP, 7z, RAR, TAR.GZ 
 Ogni formato di archivio ha una storia e un caso d'uso specifico. Conoscerli aiuta a scegliere lo strumento giusto e a non restare bloccati davanti a un file sconosciuto. 
 
 Formato Uso tipico Nota tecnica 
 ZIP Inviare cartelle via email, distribuire materiale scolastico e lavorativo, condividere software su Windows e macOS. Compatibile nativamente con Windows, macOS e Linux senza software aggiuntivo. Ogni file è compresso separatamente. 
 7z Archivi personali e backup dove la dimensione finale è importante. Compressione generalmente migliore di ZIP a parità di tempo. Formato aperto, richiede 7-Zip o software compatibile. Supporta cifratura AES-256 con password. 
 RAR Archivi multi-volume scaricati online, dove i file sono stati divisi in parti da 100–500 MB per facilitare il download. Formato proprietario di WinRAR. La decompressione è gratuita; la creazione di nuovi archivi RAR richiede la licenza. 
 TAR.GZ Distribuire codice sorgente, pacchetti software e backup su sistemi Linux e server Unix. Standard de facto nel mondo open source. TAR raccoglie i file in un unico contenitore senza comprimerli; GZ comprime il risultato. Separazione netta tra packaging e compressione.

--- Slide 18 ---
Scorciatoie evolute 
 Link simbolici e hard link 
 Un collegamento può far apparire un file in una cartella diversa senza duplicarne il contenuto fisico sul disco. I due tipi principali, link simbolico e hard link, funzionano in modo molto diverso a livello di file system. 
 Questi meccanismi sono usati dal sistema operativo per tenere strutture pulite: cartelle di configurazione che puntano a versioni aggiornate, librerie condivise tra programmi, backup efficienti senza copia dei dati. 
 Analogia: Un hard link è come avere due targhe sulla stessa porta; un link simbolico è un cartello che indica dove si trova la porta. 
 
 
 Link simbolico (symlink) È un file speciale che contiene il percorso della destinazione. Se la destinazione viene spostata o cancellata, il link risulta "rotto" e non punta più a nulla di valido. Funziona tra partizioni diverse. 
 Hard link È un secondo nome nello stesso file system che punta allo stesso inode (blocco dati) del file originale. Il dato resta sul disco finché esiste almeno un nome che vi fa riferimento. Non può attraversare partizioni diverse. 
 Collegamento Windows (.lnk) I classici file .lnk sono scorciatoie gestite da Esplora risorse: simili concettualmente ai symlink, ma non equivalenti a livello di sistema. Windows supporta anche symlink nativi tramite mklink .
