Classi e oggetti

Una classe definisce la struttura comune di un tipo: quali attributi possono descriverlo e quali metodi possono modificarlo. L’oggetto, chiamato anche istanza, è un elemento concreto creato da quella classe e conserva valori propri.

Struttura comune, dati separati

Tre conti possono offrire tutti il metodo deposita(), ma ciascuno mantiene un saldo indipendente. Modificare un’istanza non cambia automaticamente le altre.

Analogia: la classe è il progetto; ogni oggetto è una costruzione concreta realizzata da quel progetto.
Stesso tipo e stessi metodi, ma uno stato distinto per ogni istanza

Costruire un oggetto con __init__

__init__ inizializza ogni nuova istanza con i dati ricevuti. Python passa automaticamente l’oggetto appena creato nel parametro self; gli altri argomenti arrivano dalla chiamata a Prodotto(...). Il nome self è una convenzione fondamentale e __init__ non deve restituire l’oggetto: Python lo restituisce dopo l’inizializzazione.

class Prodotto: def __init__(self, nome, prezzo): self.nome = nome self.prezzo = prezzo penna = Prodotto("Penna", 1.50)
  • Prodotto("Penna", 1.50) crea una nuova istanza.
  • La nuova istanza diventa self; gli altri valori diventano nome e prezzo.
  • Le assegnazioni creano self.nome e self.prezzo sull’istanza corrente.
  • Il riferimento all’oggetto completo viene assegnato alla variabile penna.
  • penna.nome legge il suo attributo; un secondo prodotto può contenere valori diversi.

I metodi proteggono lo stato

Un metodo rappresenta un’operazione ammessa sull’oggetto. Prima di modificare gli attributi può controllare gli argomenti e rifiutare richieste che produrrebbero uno stato non valido. Scrivere direttamente conto.saldo += importo dall’esterno aggirerebbe invece la regola e distribuirebbe la validazione in più punti del programma.

class Conto: def __init__(self, saldo=0): self.saldo = saldo def deposita(self, importo): if importo <= 0: raise ValueError("Importo non valido") self.saldo += importo
conto = Conto(100) conto.deposita(50) print(conto.saldo) # 150

Stato controllato

saldo descrive la situazione corrente. La modifica avviene dentro deposita(), così ogni chiamante attraversa lo stesso controllo.

Validazione prima della modifica

Se importo <= 0, raise ValueError(...) interrompe il metodo e il saldo resta invariato. Solo un valore valido raggiunge l’ultima riga.

Passaggio implicito di self

Python passa conto come self e 50 come importo.

Composizione prima dell'ereditarietà

La composizione collega oggetti con una relazione «ha un» e permette di sostituire una parte senza cambiare l’identità dell’oggetto principale. L’ereditarietà crea invece una relazione «è un»: il sottotipo deve rispettare operazioni e aspettative del tipo base. Quando entrambe sembrano possibili, la composizione è spesso la scelta iniziale più flessibile perché riduce l’accoppiamento tra i tipi.

Composizione: contiene

class Ordine: def __init__(self, cliente): self.cliente = cliente self.righe = []

Un ordine ha un cliente e più righe. Può delegare il lavoro a questi oggetti senza copiarne il codice; le parti restano separabili e sostituibili nei test.

Ereditarietà: specializza

class Veicolo: def muovi(self): ... class Bicicletta(Veicolo): pass

Una bicicletta è un veicolo soltanto se conserva il significato delle operazioni previste da Veicolo. Ereditare solo per riutilizzare righe crea legami rigidi e sottotipi incoerenti.

Dataclass: oggetti che rappresentano dati

Quando una classe serve soprattutto a raccogliere campi, @dataclass usa le annotazioni di tipo per generare automaticamente costruttore, confronto tra istanze e rappresentazione leggibile. I campi restano normali attributi Python.

from dataclasses import dataclass @dataclass class Punto: x: float y: float p = Punto(3, 4) print(p) # Punto(x=3, y=4)

Cosa viene generato

  • Punto(3, 4) funziona senza scrivere manualmente __init__.
  • print(p) mostra nomi e valori dei campi.
  • Due istanze con gli stessi valori risultano uguali tramite ==.

Quando usarla

È adatta a record, configurazioni, coordinate e risultati strutturati. Una classe esplicita resta preferibile quando deve coordinare molte operazioni o imporre regole complesse.

Le annotazioni x: float e y: float descrivono il tipo previsto, ma non convertono né validano automaticamente i valori durante l’esecuzione.

Iterable e iteratori

Un iterable è un oggetto dal quale si può ottenere una sequenza di elementi. iter() crea l’iteratore, che conserva la posizione raggiunta; next() gli chiede un elemento alla volta.

Iterable

Liste, stringhe, dizionari e file sono attraversabili. L’iterable descrive la sorgente e, in molti casi, può creare più iteratori indipendenti.

iter()

iter(sorgente) restituisce l’oggetto che terrà memoria dell’avanzamento. Per una lista nuova, la posizione iniziale precede il primo elemento.

next()

next(iteratore) restituisce il valore corrente e avanza. Quando non restano elementi genera StopIteration.

In pratica: il ciclo for chiama iter() una volta e continua a chiamare next() finché riceve StopIteration; per questo funziona con sorgenti diverse senza conoscerne la struttura interna.

Consumare un iteratore una volta

Un iteratore rappresenta un attraversamento in corso. Ogni chiamata a next() modifica la sua posizione interna: il valore restituito non sarà prodotto di nuovo, a meno di creare un nuovo iteratore dalla sorgente.

numeri = iter([10, 20, 30]) print(next(numeri)) # 10 print(next(numeri)) # 20 print(next(numeri)) # 30
⚠️ Attenzione

La lista originale resta disponibile e consente di chiamare nuovamente iter(lista). La variabile numeri, invece, è già l’iteratore: dopo il terzo valore, un altro next(numeri) genera StopIteration. Anche lettori CSV, generatori e file aperti possono essere già parzialmente o totalmente consumati.

Conseguenza pratica

Se più parti del programma devono rileggere gli stessi valori, conserva la sorgente oppure materializza consapevolmente l’iteratore con list(...), valutando il costo in memoria.

Generatori: produrre valori con yield

La presenza di yield trasforma la funzione in una funzione generatrice. Chiamarla non esegue subito il corpo: restituisce un generatore che parte alla prima richiesta, sospende il lavoro dopo ogni valore e conserva variabili e posizione per la richiesta seguente.

def quadrati(limite): for n in range(limite): yield n * n
for valore in quadrati(4): print(valore) # 0, 1, 4, 9

Cosa accade

  1. quadrati(4) crea il generatore senza calcolare i quattro risultati.
  2. Il for richiede il primo valore; il ciclo interno arriva a yield 0 e si sospende.
  3. Alla richiesta successiva riprende dopo yield, aggiorna n e produce il valore seguente.
  4. Quando il ciclo termina, il generatore segnala automaticamente StopIteration.

In memoria rimane lo stato necessario a proseguire, non l’intera collezione dei risultati.

yield produce un valore e sospende; return termina invece definitivamente il generatore. Dopo la conclusione non può essere riavvolto.

Fonte: range() — documentazione Python ↗

Espressioni generatrici

Le due forme possono esprimere lo stesso calcolo, ma lo eseguono in momenti diversi. La list comprehension crea subito l’intera lista; l’espressione generatrice produce invece un valore alla volta, solo quando viene richiesto.

Lista immediata

quadrati = [n*n for n in range(1_000_000)]

Il milione di quadrati viene calcolato subito e conservato. È utile quando occorrono accesso per indice, più attraversamenti o la lunghezza già disponibile.

Generatore pigro

quadrati = (n*n for n in range(1_000_000))

Conserva soltanto la posizione e il calcolo da eseguire. Riduce la memoria, ma avanza in una sola direzione e va ricreato per un secondo attraversamento.

Pipeline: filtrare senza caricare tutto

Generatori collegati formano una pipeline pigra: il consumatore finale richiede un valore, e la richiesta risale le fasi fino alla sorgente. Ogni fase elabora soltanto l’elemento necessario, senza creare liste intermedie.

righe = (riga.strip() for riga in file) non_vuote = (riga for riga in righe if riga) importi = (float(riga) for riga in non_vuote) totale = sum(importi)

Il percorso di una riga

  1. file fornisce una riga alla volta.
  2. strip() rimuove spazi e fine riga.
  3. Il filtro scarta le stringhe vuote.
  4. float() converte il testo rimasto in numero.
  5. sum() consuma gli importi e aggiorna il totale.

Se una conversione fallisce, l’errore emerge soltanto quando quella riga raggiunge il consumatore.

Questa valutazione su richiesta evita lavoro inutile se il consumatore si ferma prima di esaurire la sorgente.

Regola: una pipeline è utile per log, grandi CSV e flussi che non devono stare tutti in memoria.

Moduli e pacchetti organizzano il progetto

Un modulo è un file Python importabile; raccoglie nomi correlati e crea un proprio spazio dei nomi. Un pacchetto organizza più moduli sotto un nome comune e rispecchia la struttura delle cartelle del progetto.

📄
modulo
calcoli.py può definire funzioni, classi e costanti dedicate ai calcoli.
🗂️
pacchetto
negozio/ raggruppa moduli dello stesso dominio; __init__.py ne marca esplicitamente il confine.
→
import
from negozio.calcoli import totale percorre pacchetto, modulo e nome richiesto.
progetto/ app.py negozio/ __init__.py calcoli.py modelli.py
# app.py from negozio.calcoli import totale risultato = totale([12.50, 7.00])
Regola: i moduli separano responsabilità; i pacchetti rendono visibile la relazione tra moduli senza concentrare tutto in un solo file.

Un ambiente virtuale per ogni progetto

Un ambiente virtuale crea una cartella con un interprete di riferimento e una directory separata per i pacchetti installati. In questo modo due progetti possono richiedere versioni diverse della stessa libreria senza modificare l’installazione globale.

python -m venv .venv # Linux / macOS source .venv/bin/activate # Windows PowerShell .venv\Scripts\Activate.ps1

Creazione e attivazione

  • python -m venv .venv crea l’ambiente nella cartella nascosta .venv.
  • L’attivazione modifica temporaneamente il percorso dei comandi nella shell corrente.
  • Non “entra” nel progetto: indica soltanto quali python e pip usare.
  • Chiudendo la shell l’attivazione termina; i file dell’ambiente restano disponibili.
💡 Controllo

Dopo l’attivazione, python e python -m pip devono puntare dentro .venv. La cartella dell’ambiente non si condivide nel repository: si ricrea dalle dipendenze dichiarate.

Installare pacchetti con pip

pip cerca una distribuzione compatibile, scarica il pacchetto e le dipendenze necessarie, quindi li installa nell’ambiente associato all’interprete scelto. Non importa automaticamente il pacchetto nel programma: rende soltanto disponibile il codice.

python -m pip install requests python -m pip show requests python -m pip uninstall requests

Cosa fanno i tre comandi

  • install requests risolve e installa la versione richiesta insieme alle sue dipendenze.
  • show requests mostra versione, posizione, metadati e dipendenze dichiarate.
  • uninstall requests rimuove quel pacchetto dopo conferma, ma non elimina automaticamente ogni dipendenza condivisa.

Perché python -m pip?

Rende esplicito quale interprete esegue pip e riduce il rischio di installare nell’ambiente sbagliato.

Dichiarare dipendenze riproducibili

Installare localmente non basta: il progetto deve comunicare quali pacchetti richiede e con quali vincoli. Dichiarare un intervallo esprime compatibilità prevista; registrare versioni esatte descrive invece un ambiente già risolto e riproducibile.

requirements.txt

requests==2.32.3 pytest==8.3.5

Elenco semplice installabile con python -m pip install -r requirements.txt. Il simbolo == richiede esattamente quella versione.

pyproject.toml

dependencies = [ "requests>=2.32,<3" ]

Descrive metadati e dipendenze del progetto. L’intervallo accetta aggiornamenti compatibili dalla versione 2.32 fino alla precedente alla 3.

Lock file

Registra le versioni esatte dell’intero albero, incluse le dipendenze indirette. Consente allo strumento che lo ha prodotto di ricreare lo stesso ambiente.

Distinzione: la dichiarazione dice cosa è compatibile; il lock file registra cosa è stato effettivamente scelto.

Import stabili, avvio esplicito

Importare un modulo esegue le istruzioni al suo livello principale. Per evitare richieste di input, scritture su file o avvii inattesi, il codice importabile dovrebbe limitarsi a definire funzioni, classi e costanti; l’orchestrazione appartiene a un punto di ingresso esplicito.

# negozio/calcoli.py def totale(righe): return sum(r.prezzo for r in righe) # app.py from negozio.calcoli import totale def main(): ... if __name__ == "__main__": main()

Confine utile

  • negozio/calcoli.py definisce una funzione riutilizzabile e non avvia operazioni da solo.
  • app.py importa la funzione e concentra input, output e coordinamento dentro main().
  • Quando il file è eseguito direttamente, __name__ vale "__main__" e la guardia chiama main().
  • Quando è importato, __name__ contiene il nome del modulo: la guardia è falsa e l’applicazione non parte.
  • I test possono così importare totale senza simulare l’intera interfaccia.
  • Lo stesso modulo può essere riutilizzato da un’altra applicazione senza duplicare la logica di calcolo.
