In VS Code si apre una cartella, non soltanto un file

Un programma reale è un progetto: codice, configurazioni, risorse, dipendenze, test e documentazione lavorano insieme.

Regola: usa File → Apri cartella: Explorer, ricerca, terminale ed estensioni ricevono lo stesso contesto.
Il progetto dà contesto ai singoli file

VS Code: una scrivania modulare

Visual Studio Code è un editor multipiattaforma: alcune funzioni sono integrate, altre arrivano tramite estensioni del linguaggio o del servizio usato.

🗂️

Explorer

File, cartelle, ricerca e struttura del progetto.

✍️

Editor

Schede, più pannelli, selezioni multiple e navigazione.

⌘

Command Palette

Un punto unico per cercare azioni senza ricordare i menu.

💡 Distinzione utile

VS Code e Visual Studio sono prodotti diversi: il primo è un editor estendibile; il secondo è un IDE completo, soprattutto per .NET e C++ su Windows.

Fonte: Documentazione ufficiale Visual Studio Code ↗

Cinque pannelli, cinque compiti distinti

L’area inferiore di VS Code ospita viste separate: puoi aprirle, chiuderle e passare dall’una all’altra secondo il lavoro da svolgere.

⌨️

Terminale

Esegue comandi nella shell: avvio del programma, installazione di dipendenze e script.

≡

Output

Raccoglie i log prodotti da VS Code, estensioni, compilatori e altri servizi.

△

Problemi

Elenca errori e avvisi rilevati nei file, con collegamenti alle righe interessate.

◎

Console di debug

Mostra messaggi e permette di osservare o valutare valori durante un’esecuzione controllata.

✓

Test

Organizza i test disponibili, li esegue e distingue controlli superati, falliti o ignorati.

IntelliSense legge il contesto del progetto

🎨

Evidenziazione sintattica

Colora parole chiave, stringhe e commenti. Aiuta a leggere, ma non dimostra che il codice sia corretto.

💬

Completamento

Suggerisce nomi, parametri e membri disponibili. La qualità dipende dal linguaggio e dal servizio installato.

﹏

Diagnostica

Sottolinea errori e avvisi trovati dal parser, dal compilatore o da strumenti di analisi.

↗

Navigazione

Vai alla definizione, trova riferimenti e rinomina simboli nel progetto, quando il linguaggio lo supporta.

In pratica: un suggerimento accelera il lavoro; compilatore e test stabiliscono se funziona.

Le estensioni aggiungono capacità

Un'estensione può supportare un linguaggio, collegare un servizio, aggiungere un tema oppure integrare test e strumenti di qualità.

⚠️ Prima di installare

Controlla editore, permessi, manutenzione, documentazione e necessità reale. Più estensioni significano anche più aggiornamenti e possibili conflitti.

Il debugger integrato di VS Code

Con una configurazione di debug adatta al linguaggio, VS Code sospende l’esecuzione in un punto scelto e permette di controllare, passo dopo passo, come cambiano dati e chiamate.

●

Breakpoint

Una riga in cui sospendere l'esecuzione.

↧

Avanzamento

Step over esegue la riga; step into entra nella funzione chiamata.

◉

Variabili

Mostra valori e strutture nello stato corrente.

⌁

Call stack

Ricostruisce la sequenza di chiamate che ti ha portato lì.

💡 Metodo

Formula un'ipotesi, posiziona il breakpoint prima del punto sospetto e confronta il valore atteso con quello reale.

Tre controlli dentro il flusso di VS Code

🧹

Formatter

Uniforma spazi, rientri e stile. Riduce discussioni estetiche, ma non verifica la logica.

🔎

Linter / analisi

Segnala pattern rischiosi, errori probabili e violazioni delle regole configurate.

✓

Test

Esegue casi controllati e confronta risultato ottenuto e risultato atteso.

In pratica

In VS Code formatter, linter e test possono partire da estensioni, task o comandi del progetto, ma devono usare configurazioni condivise e produrre risultati visibili al team.

VS Code è un ambiente, non una scorciatoia.

Sai aprire il progetto, usare pannelli, IntelliSense, estensioni, terminale, debugger e controlli di qualità senza confonderli con gli strumenti sottostanti.
