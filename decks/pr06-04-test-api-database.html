Un test rende verificabile una promessa

Un test descrive un comportamento osservabile: prepara le condizioni, esegue una sola azione significativa e confronta ciò che accade con un risultato atteso esplicito.

Arrange

Costruisce dati, oggetti e dipendenze necessari. Lo stato iniziale deve essere leggibile: chi esamina il test deve capire subito da quale situazione si parte.

Act

Invoca la funzione o il metodo da verificare. Se questa fase contiene molte operazioni, diventa difficile attribuire il fallimento a una causa precisa.

Assert

Confronta risultato ottenuto e atteso. Può controllare un valore restituito, un’eccezione oppure un cambiamento nello stato dell’oggetto.

Regola: nome, dati e confronto devono spiegare quale promessa si è rotta.

Assert: il controllo minimo

L’istruzione assert documenta una condizione che il programmatore ritiene necessariamente vera in quel punto. Se la condizione è falsa, Python solleva AssertionError.

def media(valori): if not valori: raise ValueError("Lista vuota") return sum(valori) / len(valori) assert media([6, 8, 10]) == 8

Due controlli diversi

  • La funzione solleva ValueError per un input vuoto previsto dal suo contratto.
  • Il test usa assert per dichiarare che il risultato del caso valido deve essere 8.
  • Un messaggio opzionale può aggiungere contesto: assert condizione, "motivo".
  • Confronti tra numeri decimali richiedono spesso una tolleranza, non l’uguaglianza esatta.
⚠️ Distinzione

Gli assert possono essere disattivati avviando Python con ottimizzazioni. Non usarli per validare input utente, autorizzazioni o condizioni necessarie alla sicurezza: in quei casi servono controlli ed eccezioni espliciti.

Test strutturati con unittest

unittest raccoglie più verifiche in una suite, esegue automaticamente i metodi il cui nome inizia con test_ e distingue fallimenti delle asserzioni da errori inattesi nel codice.

import unittest class TestMedia(unittest.TestCase): def test_valori_normali(self): self.assertEqual(media([6, 8, 10]), 8) def test_lista_vuota(self): with self.assertRaises(ValueError): media([]) if __name__ == "__main__": unittest.main()

Come leggere la struttura

  • TestCase fornisce metodi di confronto e gestione delle eccezioni.
  • Ogni metodo test_... è un caso indipendente.
  • assertEqual() mostra valore atteso e ottenuto quando fallisce.
  • assertRaises() verifica sia il tipo dell’errore sia il punto in cui deve comparire.
  • unittest.main() avvia la scoperta nel file eseguito direttamente.

Un fallimento deve aiutare a diagnosticare

Il risultato di una suite non serve soltanto a dire «rosso» o «verde»: deve indicare quale comportamento è cambiato e fornire abbastanza contesto per riprodurre il problema.

Fallimento di un’asserzione

AssertionError: 7.5 != 8

Il test è arrivato al confronto, ma il valore prodotto non coincide con quello atteso. Il nome del test e i dati preparati devono chiarire il caso.

Errore durante l’esecuzione

TypeError: unsupported operand...

Il test non ha raggiunto il confronto: il codice ha sollevato un’eccezione inattesa. La traccia indica file, funzione e riga da cui iniziare l’indagine.

💡 Lettura

Correggi prima gli errori che impediscono l’esecuzione, poi valuta i fallimenti delle aspettative. Non modificare il risultato atteso soltanto per rendere verde la suite.

Preparare e isolare il contesto

setUp() ricrea le condizioni prima di ogni test. Oggetti nuovi, file temporanei e database separati impediscono che il risultato dipenda da ciò che un altro caso ha lasciato in memoria o sul disco.

class TestCarrello(unittest.TestCase): def setUp(self): self.carrello = Carrello() def test_inizialmente_vuoto(self): self.assertEqual( self.carrello.totale(), 0 )

Isolamento

Il framework chiama setUp() prima di ogni metodo di test: modificare self.carrello in un caso non influenza quello successivo.

Pulizia

tearDown() può chiudere connessioni o rimuovere risorse create dal test. I context manager e le directory temporanee riducono il rischio di dimenticarle.

Determinismo

Stesso input e stesso contesto devono produrre lo stesso risultato. Rete, orologio e casualità vanno controllati, simulati o sostituiti.

Casi normali, limite ed errore

Una funzione non è verificata se il test copre soltanto l’esempio più comodo. I casi vanno scelti a partire dalle decisioni presenti nel codice e dal contratto dichiarato.

Normale

Usa valori tipici e controlla il risultato principale. Per media(): più numeri validi, anche con un risultato decimale.

Limite

Prova zero, un solo elemento, lista vuota e valori sul confine tra due rami. Sono i punti in cui confronti e indici cambiano comportamento.

Errore

Verifica tipo sbagliato, dato mancante o formato non valido. Non basta che «fallisca»: deve sollevare l’eccezione prevista senza alterare lo stato.

💡 Buona domanda

Quale input attraversa un ramo non ancora provato? Un elenco lungo di casi quasi identici aggiunge meno valore di pochi casi scelti sui confini.

Eseguire una suite e localizzare la regressione

Una suite permette di rieseguire in pochi secondi le promesse già verificate. Dopo una modifica, un test che prima passava e ora fallisce segnala una possibile regressione.

python -m unittest python -m unittest -v python -m unittest \ test_calcoli.TestMedia.test_lista_vuota

Tre livelli di esecuzione

  • Senza argomenti, la scoperta cerca i file di test secondo le convenzioni.
  • Con -v, il nome di ogni caso rende visibile ciò che è stato eseguito.
  • Indicando modulo, classe e metodo si riproduce rapidamente un solo fallimento.
  • La suite completa va comunque rieseguita prima di considerare conclusa la correzione.

Un test affidabile non dipende dall’ordine in cui gli altri test vengono eseguiti.

Un’API HTTP espone risorse

Il client invia una richiesta composta da metodo, URL, intestazioni e corpo opzionale. Il server elabora la richiesta e restituisce stato, intestazioni e contenuto: i due programmi possono evolvere separatamente finché rispettano questo contratto.

Metodo

GET legge, POST crea, PUT sostituisce, PATCH modifica parzialmente e DELETE rimuove. Il metodo esprime l’azione richiesta sulla risorsa.

URL

https://api.azienda.it/prodotti/42 identifica il prodotto 42. La query string può filtrare o ordinare una raccolta senza cambiare l’identità dell’endpoint.

Risposta

Il codice di stato comunica l’esito; gli header descrivono metadati e formato; il corpo contiene la rappresentazione, spesso JSON. Non tutte le risposte possiedono un corpo.

In pratica: URL e metodo formulano la domanda; stato e corpo costituiscono la risposta.
Fonte: HTTP Semantics — RFC 9110 ↗

Fare una richiesta con requests

requests.get() costruisce una richiesta HTTP e restituisce un oggetto Response. Imposta sempre un timeout: senza un limite, il programma può restare bloccato in attesa della rete.

import requests risposta = requests.get( "https://api.azienda.it/prodotti", params={"categoria": "ufficio"}, timeout=10, ) risposta.raise_for_status() prodotti = risposta.json()

Riga per riga

  • params codifica i parametri nella query string senza concatenarli a mano.
  • timeout=10 limita l’attesa della risposta; non impone che l’intero download termini in dieci secondi.
  • raise_for_status() solleva un errore per gli stati HTTP 4xx e 5xx.
  • json() decodifica il corpo: può fallire se la risposta non contiene JSON valido.
Fonte: requests.get() — documentazione Requests ↗Fonte: Response.raise_for_status() — documentazione Requests ↗

Il JSON ricevuto va ancora verificato

Uno stato 200 conferma che il server ha gestito la richiesta, non che il corpo possieda tutti i campi attesi dall’applicazione. Il client deve controllare forma e valori prima di usarli.

dati = risposta.json() if not isinstance(dati, list): raise ValueError("Elenco atteso") for prodotto in dati: if "id" not in prodotto: raise ValueError("ID mancante")

Contratto locale

  • Controlla se la radice è una lista, un oggetto o un altro valore JSON.
  • Verifica i campi indispensabili prima di accedervi.
  • Distingui un campo assente da un campo presente con valore null.
  • Converti date e numeri soltanto dopo averne validato il formato.

Le risposte esterne sono input non fidato, anche quando provengono da un servizio noto.

Stato HTTP ed errori di rete

Una risposta ricevuta può comunque indicare un errore. Inoltre DNS, connessione, TLS o timeout possono fallire prima della risposta.

Codici frequenti

200 riuscita · 201 creata · 400 richiesta errata · 401/403 accesso negato · 404 assente · 500 errore server.

try: risposta = requests.get(url, timeout=10) risposta.raise_for_status() except requests.Timeout: print("Servizio troppo lento") except requests.RequestException as errore: print("Richiesta fallita", errore)

Autenticazione, pagine e limiti

Le API reali raramente restituiscono tutto senza regole: identificano il client, dividono raccolte grandi in più risposte e proteggono il servizio da richieste eccessive.

Token

Si invia nell’header previsto, spesso come Authorization. Va letto da configurazione o variabili d’ambiente, mai scritto nel codice, nei log o nel repository.

Paginazione

La risposta può fornire numero di pagina, URL successivo o cursore opaco. Il client deve fermarsi quando il server non indica altri risultati.

Rate limit

Lo stato 429 segnala troppe richieste. Attendi il tempo indicato, applica un ritardo crescente e non ripetere all’infinito operazioni fallite.

Seguire una paginazione senza perdere dati

Una singola risposta può contenere soltanto una parte della raccolta. Il ciclo conserva i risultati già ricevuti e usa l’indicazione del server per richiedere la pagina successiva.

url = "https://api.azienda.it/prodotti" prodotti = [] while url is not None: risposta = requests.get(url, timeout=10) risposta.raise_for_status() pagina = risposta.json() prodotti.extend(pagina["risultati"]) url = pagina.get("prossima")

Condizioni da controllare

  • url parte dall’endpoint iniziale e diventa None alla fine.
  • extend() aggiunge gli elementi, non la lista come singolo elemento.
  • Ogni pagina va validata prima di leggerne i campi.
  • Timeout, errori HTTP e limiti di frequenza restano possibili a ogni iterazione.
  • Per raccolte enormi conviene elaborare una pagina alla volta invece di conservarle tutte.

SQLite: un database dentro un file

SQLite conserva schema, tabelle e indici in un singolo file e non richiede un server separato. L’applicazione interroga il motore attraverso SQL, mentre il database gestisce persistenza, vincoli e transazioni.

Tabella

Ogni riga rappresenta un record; le colonne ne definiscono attributi e tipi dichiarati. Lo schema rende esplicita una struttura che in un CSV resterebbe implicita.

Chiave primaria

Identifica ogni record senza ambiguità. Altre tabelle possono conservare quel valore come chiave esterna per esprimere una relazione.

Query SQL

INSERT, SELECT, UPDATE e DELETE modificano o interrogano i dati. Filtri e indici evitano di caricare tutto nel programma.

Quando usarlo: dati strutturati con ricerche, vincoli e aggiornamenti coordinati; non come semplice sostituto di ogni file.

Creare tabella e connessione

connect() apre il file del database o lo crea se manca. Il blocco with db delimita una transazione: conferma le istruzioni concluse correttamente e annulla quelle del blocco quando emerge un errore.

import sqlite3 db = sqlite3.connect("negozio.db") try: with db: db.execute(""" CREATE TABLE IF NOT EXISTS prodotti ( id INTEGER PRIMARY KEY, nome TEXT NOT NULL, prezzo REAL NOT NULL CHECK (prezzo >= 0) ) """) finally: db.close()

Vincoli dichiarati nello schema

  • PRIMARY KEY assegna a ogni riga un identificatore unico.
  • NOT NULL impedisce l’assenza del nome e del prezzo.
  • CHECK rifiuta prezzi negativi anche se il controllo manca nel programma.
  • IF NOT EXISTS rende ripetibile la creazione senza cancellare la tabella esistente.
  • finally libera la connessione indipendentemente dall’esito.
Fonte: sqlite3.connect() — documentazione Python ↗

La transazione protegge un’operazione completa

Una transazione raggruppa più istruzioni che devono riuscire insieme. Se una fallisce, il rollback evita di lasciare il database in uno stato parziale.

with db: db.execute( "UPDATE conti SET saldo = saldo - ? WHERE id = ?", (importo, conto_origine), ) db.execute( "UPDATE conti SET saldo = saldo + ? WHERE id = ?", (importo, conto_destinazione), )

Una sola unità logica

Un trasferimento non è formato da due modifiche indipendenti: addebito e accredito devono essere entrambi persistiti oppure entrambi annullati.

  • Il commit rende definitive tutte le modifiche del blocco.
  • Un’eccezione provoca il rollback automatico del contesto.
  • I vincoli dello schema possono interrompere la transazione.
  • Il codice deve verificare che i record coinvolti esistano e che l’operazione sia ammessa.

Parametri SQL, mai concatenazione

I segnaposto separano la struttura dell’istruzione dai valori forniti al momento dell’esecuzione. Il driver codifica correttamente stringhe, numeri e valori nulli e impedisce che un dato venga interpretato come sintassi SQL.

Da evitare

sql = "SELECT * FROM prodotti WHERE nome = '" + nome + "'"

Virgolette e frammenti SQL presenti in nome possono cambiare il significato della query. Aggiungere manualmente escape è fragile e dipende dal database.

Corretto

righe = db.execute( "SELECT * FROM prodotti WHERE nome = ?", (nome,), ).fetchall()

Il punto interrogativo occupa il posto di un valore. La tupla (nome,) contiene un solo elemento: la virgola è necessaria. I segnaposto non sostituiscono nomi di tabelle o colonne.

⚠️ Regola

Parametrizza ogni valore proveniente dall’esterno, anche quando sembra numerico o già controllato. La validazione applicativa e la parametrizzazione risolvono problemi diversi e servono entrambe.

Dal CRUD a una funzione verificabile

Raggruppa ogni operazione del database in una funzione con input, risultato e responsabilità chiari. Passare la connessione dall’esterno separa la logica dall’apertura del file e facilita i test con un database temporaneo.

def aggiungi_prodotto(db, nome, prezzo): cursore = db.execute( "INSERT INTO prodotti(nome, prezzo) VALUES (?, ?)", (nome, prezzo), ) return cursore.lastrowid

Create

INSERT aggiunge un record. lastrowid restituisce l’identificatore assegnato, utile per collegare subito altri dati.

Read

SELECT restituisce righe. La funzione deve chiarire se produce una riga, una lista o None quando non trova risultati.

Update / Delete

UPDATE e DELETE devono usare una condizione precisa. Il numero di righe coinvolte aiuta a rilevare identificatori inesistenti o filtri troppo ampi.

Leggere, aggiornare e cancellare con funzioni chiare

Ogni funzione espone un’operazione del dominio e nasconde i dettagli SQL al resto del programma. Parametri e valori restituiti costituiscono il suo contratto.

def trova_prodotto(db, prodotto_id): return db.execute( "SELECT id, nome, prezzo " "FROM prodotti WHERE id = ?", (prodotto_id,), ).fetchone()
def elimina_prodotto(db, prodotto_id): cursore = db.execute( "DELETE FROM prodotti WHERE id = ?", (prodotto_id,), ) return cursore.rowcount

Risultati espliciti

  • fetchone() restituisce una riga oppure None.
  • Elencare le colonne rende stabile e leggibile il formato del risultato.
  • rowcount indica quante righe sono state eliminate.
  • Un risultato pari a zero può significare che l’identificatore non esiste.
  • Il chiamante decide come tradurre quel caso: messaggio, eccezione o risposta HTTP.

Queste funzioni possono essere testate passando una connessione SQLite in memoria.
