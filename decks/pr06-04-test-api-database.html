Un test rende verificabile una promessa

Un test prepara un caso, esegue il comportamento e confronta il risultato con ciò che dovrebbe accadere.

Arrange

Prepara dati e dipendenze.

Act

Esegue la funzione o il metodo.

Assert

Confronta risultato ottenuto e atteso.

Regola: un test deve fallire per un motivo comprensibile.

Assert: il controllo minimo

L'istruzione assert esprime una condizione che deve essere vera. È utile nei test e per invarianti interne, non per validare input utente.

def media(valori): if not valori: raise ValueError("Lista vuota") return sum(valori) / len(valori) assert media([6, 8, 10]) == 8
⚠️ Distinzione

Gli assert possono essere disattivati dall'interprete. Per errori previsti dell'utente usa eccezioni esplicite.

Test strutturati con unittest

La libreria standard scopre classi e metodi di test, raccoglie risultati e mostra errori riproducibili.

import unittest class TestMedia(unittest.TestCase): def test_valori_normali(self): self.assertEqual(media([6, 8, 10]), 8) def test_lista_vuota(self): with self.assertRaises(ValueError): media([]) if __name__ == "__main__": unittest.main()
Fonte: Modulo unittest — documentazione Python ↗

Preparare e isolare il contesto

setUp() ricrea le condizioni prima di ogni test. File temporanei e oggetti nuovi impediscono che un test sporchi il successivo.

class TestCarrello(unittest.TestCase): def setUp(self): self.carrello = Carrello() def test_inizialmente_vuoto(self): self.assertEqual( self.carrello.totale(), 0 )

Isolamento

Ogni test parte da uno stato noto.

Determinismo

Stesso input, stesso risultato: rete, orologio e casualità vanno controllati o sostituiti.

Casi normali, limite ed errore

Una funzione non è verificata se il test copre soltanto l'esempio più comodo.

Normale

Valori tipici e risultato atteso.

Limite

Zero, uno, lista vuota, valore massimo o confine tra due rami.

Errore

Tipo sbagliato, dato mancante, file assente o risposta non valida.

Un'API HTTP espone risorse

Il client invia una richiesta a un URL; il server risponde con stato, intestazioni e contenuto.

Metodo

GET legge, POST crea, PUT/PATCH modifica, DELETE rimuove.

URL

https://api.azienda.it/prodotti/42 identifica una risorsa.

Risposta

Codice di stato, header e corpo spesso codificato in JSON.

Fonte: HTTP Semantics — RFC 9110 ↗

Fare una richiesta con requests

Imposta sempre un timeout: senza limite, il programma può restare in attesa indefinitamente.

import requests risposta = requests.get( "https://api.azienda.it/prodotti", params={"categoria": "ufficio"}, timeout=10, ) risposta.raise_for_status() prodotti = risposta.json()
Fonte: Requests Quickstart — documentazione ufficiale ↗

Stato HTTP ed errori di rete

Una risposta ricevuta può comunque indicare un errore. Inoltre DNS, connessione, TLS o timeout possono fallire prima della risposta.

Codici frequenti

200 riuscita · 201 creata · 400 richiesta errata · 401/403 accesso negato · 404 assente · 500 errore server.

try: risposta = requests.get(url, timeout=10) risposta.raise_for_status() except requests.Timeout: print("Servizio troppo lento") except requests.RequestException as errore: print("Richiesta fallita", errore)
Fonte: Domain Name System — ICANN ↗

Autenticazione, pagine e limiti

Le API reali raramente restituiscono tutto senza regole: richiedono credenziali, dividono i risultati e limitano la frequenza.

Token

Si invia nell'header previsto. Non va scritto nel codice o pubblicato nel repository.

Paginazione

La risposta indica pagina successiva, cursore o numero totale di risultati.

Rate limit

Se arriva 429, attendi secondo le indicazioni del server invece di riprovare senza pausa.

SQLite: un database dentro un file

SQLite conserva tabelle, relazioni e indici in un singolo file, senza richiedere un server separato.

Tabella

Righe con la stessa struttura di colonne.

Chiave primaria

Identifica ogni record senza ambiguità.

Query SQL

Inserisce, cerca, aggiorna e cancella dati.

Quando usarlo: dati strutturati, ricerche e aggiornamenti più sicuri di un CSV.
Fonte: Modulo sqlite3 — documentazione Python ↗

Creare tabella e connessione

Il blocco with db conferma o annulla la transazione; finally chiude la connessione anche in caso di errore.

import sqlite3 db = sqlite3.connect("negozio.db") try: with db: db.execute(""" CREATE TABLE IF NOT EXISTS prodotti ( id INTEGER PRIMARY KEY, nome TEXT NOT NULL, prezzo REAL NOT NULL CHECK (prezzo >= 0) ) """) finally: db.close()

Parametri SQL, mai concatenazione

I segnaposto separano istruzione e dati, gestiscono correttamente i tipi e prevengono SQL injection.

Da evitare

sql = "SELECT * FROM prodotti WHERE nome = '" + nome + "'"

Il dato può cambiare il significato della query.

Corretto

righe = db.execute( "SELECT * FROM prodotti WHERE nome = ?", (nome,), ).fetchall()

La query resta separata dal valore.

Dal CRUD a una funzione verificabile

Raggruppa ogni operazione del database in una funzione con input, risultato e responsabilità chiari. Passare la connessione facilita i test con un database temporaneo.

def aggiungi_prodotto(db, nome, prezzo): cursore = db.execute( "INSERT INTO prodotti(nome, prezzo) VALUES (?, ?)", (nome, prezzo), ) return cursore.lastrowid

Create

INSERT aggiunge un record.

Read

SELECT restituisce righe.

Update / Delete

Modificano o rimuovono record selezionati.
