Non tutti gli strumenti fanno lo stesso lavoro

Puoi scrivere codice anche in un editor semplice. La differenza è quanta assistenza ricevi prima, durante e dopo la scrittura.

📄

Editor di testo

Modifica testo semplice. È rapido, ma conosce poco o nulla del linguaggio e del progetto.

⌨️

Editor di codice

Aggiunge colori, completamento, ricerca nel progetto, estensioni e spesso terminale e Git.

🧰

IDE

Integra editor, compilazione, debug, test, refactoring e strumenti specifici per una piattaforma.

Analogia: quaderno, banco attrezzato, laboratorio completo.

Si apre una cartella, non soltanto un file

Un programma reale è un progetto: codice, configurazioni, risorse, dipendenze, test e documentazione lavorano insieme.

Regola: apri la cartella principale del progetto, così lo strumento può comprenderne la struttura.
Il progetto dà contesto ai singoli file

VS Code: una scrivania modulare

Visual Studio Code è un editor multipiattaforma: alcune funzioni sono integrate, altre arrivano tramite estensioni del linguaggio o del servizio usato.

🗂️

Explorer

File, cartelle, ricerca e struttura del progetto.

✍️

Editor

Schede, più pannelli, selezioni multiple e navigazione.

⌘

Command Palette

Un punto unico per cercare azioni senza ricordare i menu.

▤

Pannello

Terminale, output, problemi, debug e test.

💡 Distinzione utile

VS Code e Visual Studio sono prodotti diversi: il primo è un editor estendibile; il secondo è un IDE completo, soprattutto per .NET e C++ su Windows.

Mentre scrivi, lo strumento legge il contesto

🎨

Evidenziazione sintattica

Colora parole chiave, stringhe e commenti. Aiuta a leggere, ma non dimostra che il codice sia corretto.

💬

Completamento

Suggerisce nomi, parametri e membri disponibili. La qualità dipende dal linguaggio e dal servizio installato.

﹏

Diagnostica

Sottolinea errori e avvisi trovati dal parser, dal compilatore o da strumenti di analisi.

↗

Navigazione

Vai alla definizione, trova riferimenti e rinomina simboli nel progetto, quando il linguaggio lo supporta.

In pratica: un suggerimento accelera il lavoro; compilatore e test stabiliscono se funziona.

Il debugger ferma il tempo

Invece di aggiungere decine di stampe, puoi sospendere il programma e osservare che cosa sta succedendo.

●

Breakpoint

Una riga in cui sospendere l'esecuzione.

↧

Step

Avanza una istruzione o entra in una funzione.

◉

Variabili

Mostra valori e strutture nello stato corrente.

⌁

Call stack

Ricostruisce la sequenza di chiamate che ti ha portato lì.

💡 Metodo

Formula un'ipotesi, posiziona il breakpoint prima del punto sospetto e confronta il valore atteso con quello reale.

Git registra modifiche, non “salva nel cloud”

L'integrazione grafica mostra file modificati, differenze, branch e conflitti. Le operazioni restano quelle di Git.

In pratica: modifica → controlla il diff → stage → commit → eventualmente push.

Diff

Confronta prima e dopo, riga per riga.

Commit

Registra un insieme coerente di modifiche locali.

Branch

Permette di lavorare su una linea separata.

Remote

Sincronizza con GitHub o un altro server quando fai pull o push.

Formatter, linter e test: tre controlli diversi

🧹

Formatter

Uniforma spazi, rientri e stile. Riduce discussioni estetiche, ma non verifica la logica.

🔎

Linter / analisi

Segnala pattern rischiosi, errori probabili e violazioni delle regole configurate.

✓

Test

Esegue casi controllati e confronta risultato ottenuto e risultato atteso.

Automazione utile

Salvataggio automatico, format on save e test rapidi sono comodi soltanto se il team condivide configurazioni e regole.

Altri strumenti noti: più leggeri o più specializzati

Sublime Text

Editor rapido e multipiattaforma con selezioni multiple, progetti, pacchetti e build configurabili.

Notepad++

Editor leggero per Windows, utile per modifiche rapide, ricerca, sintassi e plugin.

Locale, remoto o nel browser?

💻

Locale

File e strumenti girano sul tuo computer. Hai controllo e puoi lavorare offline, ma devi configurare l'ambiente.

↗

Remoto

L'interfaccia è locale, mentre codice, terminale e processi vivono su server, container, WSL o SSH.

☁️

Browser / cloud

L'ambiente è accessibile via web. Riduce il setup iniziale, ma dipende da account, rete, limiti e costi del servizio.

⚠️ Dati e segreti

Prima di usare ambienti remoti, verifica dove vengono conservati codice, credenziali, log e output del progetto.

Fonte: Remote Development — VS Code ↗

Assistenti IA: proposta, non autorità

Completamento predittivo, chat e agenti possono spiegare codice, proporre modifiche e automatizzare attività. Il risultato va trattato come una modifica di terzi.

Regola: leggi il diff, esegui i test, controlla dipendenze e licenze, non condividere segreti.

Contesto

Decidi quali file, dati e istruzioni può leggere lo strumento.

Verifica

Compilazione, analisi e test restano necessari anche se la proposta “sembra giusta”.

Responsabilità

Chi accetta la modifica resta responsabile di sicurezza, correttezza e manutenzione.

Esercizio: esplora senza installare tutto

Parte A · Orientamento

Apri una cartella-progetto e individua Explorer, editor, ricerca, terminale e pannello dei problemi.

Parte B · Scrittura

Crea un file breve, osserva colori e suggerimenti, poi introduci volontariamente un errore di sintassi.

Parte C · Esecuzione

Salva, esegui dal terminale e collega l'eventuale messaggio di errore alla riga corretta.

Parte D · Controllo

Apri il diff Git, descrivi la modifica e crea un commit con un messaggio significativo.

Obiettivo: comprendere il flusso, non memorizzare ogni pulsante.
