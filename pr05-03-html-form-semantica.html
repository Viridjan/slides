e stile

Come una pagina raccoglie dati dall’utente, come si dà un significato alle sue parti e come, con il CSS, si separa il contenuto dall’aspetto.

I moduli (form)

Un <form> è il contenitore in cui l’utente inserisce dati: un contatto, un’iscrizione, una ricerca. Due attributi dicono dove finiscono i dati e come vengono spediti.

💡 In pratica

action è l’indirizzo che riceve i dati; method è il modo in cui viaggiano (di solito post).

<form action="/invia" method="post"> … campi … <button>Invia</button> </form>

I campi di input

Il tag <input> cambia comportamento in base al suo attributo type: lo stesso tag diventa casella di testo, password o casella da spuntare.

Etichette e controlli

Un campo senza etichetta è un indovinello. Pochi elementi completano il modulo e lo rendono usabile da tutti.

<label>

Il testo che spiega il campo. Collegato all’input, permette di cliccare l’etichetta per attivarlo ed è letto dagli screen reader.

<textarea>

Come un input di testo, ma su più righe: perfetto per un messaggio o una nota.

<select>

Un menù a tendina di opzioni, quando le scelte sono molte e note in anticipo.

<button>

Il pulsante che invia il modulo o compie un’azione. Chiaro nel testo: «Invia», non «OK».

HTML che ha un significato

Si potrebbe costruire tutto con <div> anonimi. La semantica usa invece tag che dicono a cosa serve ogni zona: intestazione, menù, contenuto, piè di pagina.

ogni zona è un elemento con un nome parlante

Perché la semantica conta

Non è pignoleria: tag con un significato aiutano macchine e persone a capire la pagina.

🧑‍🦽

Accessibilità

Gli screen reader saltano al <main> o scorrono il <nav>: chi non vede naviga per zone, non a tentoni.

🔍

Motori di ricerca

Google capisce meglio la pagina quando le sue parti sono etichettate, e la indicizza meglio.

🧩

Manutenzione

Un <footer> si trova a colpo d’occhio; mille <div> uguali no. Il codice resta leggibile nel tempo.

Regola: usa <div> solo quando nessun tag con un significato adatto esiste già.

Separare contenuto e aspetto

HTML dice cosa è una cosa; il CSS dice come appare: colori, dimensioni, spazi, posizioni. Sono due mestieri distinti, ed è giusto tenerli separati.

Analogia: l’HTML è lo scheletro, il CSS è il vestito.
/* CSS */ h1 { color: teal; font-size: 40px; } p { line-height: 1.5; }

Collegare il CSS

Le regole di stile possono stare in tre posti. Per un vero sito, uno solo è la scelta giusta.

Nell’attributo

style="…" dentro il singolo tag. Rapido per una prova, ingestibile su tante pagine.

Nel <head>

Un blocco <style> vale per l’intera pagina. Utile per un file solo.

File esterno ✓

Un file .css collegato con <link> veste tutte le pagine insieme: cambi una riga, cambia il sito.

💡 Selettori

Nel CSS scrivi il nome dell’elemento (p, h1) e poi, tra graffe, le regole. Così lo stile trova gli elementi da vestire.

Verifica: forma e significato

1 · Campo giusto

Devi far scegliere una sola taglia tra S, M e L. Quale type di <input> usi, e perché non checkbox?

2 · Etichetta smarrita

Un modulo ha solo caselle senza testo accanto. Quale tag aggiungi e che vantaggio dà a chi usa uno screen reader?

3 · div o main?

Devi racchiudere il contenuto principale della pagina. Meglio <div> o <main>? Motiva la scelta.

4 · Un colore per tutto il sito

Vuoi lo stesso stile su dieci pagine, modificabile in un punto solo. Dove metti il CSS?

Dalla pagina al programma.

Sai raccogliere dati con i form, dare un significato alle parti della pagina e separarne l’aspetto con il CSS. Con l’HTML in mano, il passo successivo è la logica: Python.
